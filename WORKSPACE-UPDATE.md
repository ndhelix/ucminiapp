# Рабочие разделы CRM в Mini App

Реализованы этапы 1–7: права доступа, клиенты, события, задачи, переписка, уведомления, финансы, аналитика и остальные рабочие разделы CRM.

## Обновление

1. Выполнить в БД CRM скрипт `ConsGroupCrm/data/miniapp-stages-4-6.sql`. Он создаёт `dbo.MiniAppOperations` — журнал идентификаторов запросов, предотвращающий повторное создание задачи, комментария или сообщения после сетевого сбоя. Скрипт совместим с SQL Server 2008 R2 и допускает повторный запуск.
2. Собрать и опубликовать CRM `ConsGroupCrm/src/CRM/ConsGroupCrm.csproj` обычным способом.
   Сервер должен получить новую сборку, содержащую `MiniAppWorkspace.cs`, `MiniAppMissions.cs`, `MiniAppMessages.cs`, `MiniAppAnalytics.cs`, `MiniAppOperations.cs` и `CrmEventEffects.cs`.
   Изменён и `EventsController`: CRM и Mini App используют общие правила напоминаний.
3. В каталоге `CrmMiniApp` выполнить `npm run build`.
4. При настроенной публикации из ветки `gh-pages` выполнить `npm run deploy`.
   Если GitHub Pages настроен на GitHub Actions, публиковать через соответствующий workflow.
5. Закрыть и снова открыть Mini App в Telegram.

Для этапов 4–6 нужна таблица `dbo.MiniAppOperations` из указанного скрипта. Бизнес-данные сохраняются в существующих таблицах CRM и bil.
Обновить также `Web.config`: `httpRuntime maxRequestLength="11264"` позволяет передавать вложения до 10 МБ с накладными расходами формы. Остальные настройки рабочего Web.config сохранить.
Сначала обновляется CRM, затем Mini App: новый интерфейс требует `/MiniApp/Lookups` и новых методов карточек.
Новый `dist/404.html` нужен для обновления вложенных страниц на GitHub Pages; публикуйте весь `dist`.

## Права

Вход по-прежнему требует подписанные Telegram initData, активного сотрудника и MiniappUserLevel 1 или 2.
Авторизация не принимает ManagerId или CompanyId из браузера.
Разделы и действия определяются должностью и настоящей ролью `admin` в CRM.
Уровень MiniappUserLevel=2 сам по себе не даёт полномочий администратора CRM.
Для надёжной привязки сотруднику следует заполнить TelegramId; резервный поиск по username не заменяет уже заданный TelegramId.

Списки и карточки ограничены компанией сотрудника и правилами видимости клиентов CRM.
Должность Observer не может редактировать данные; чувствительные поля скрываются.
Балансы и последние операции **в карточке клиента** показываются администратору, директору или секретарю.
Общий раздел **«Платежи от клиентов» — только для роли admin**, как в CRM.
Задачи доступны по `AllowedToSeeMissions`; редактирование запрещено Observer. Все задачи — только текущей компании.
Переписка — для клиентов-подписчиков компании 8 с TelegramId, без скрытия чувствительных данных. Отправка — admin либо должность с `AllowedToWriteMessages`, только через активного у клиента бота.
Уведомления повторяют фильтры CRM Notifications (RTTM), скрывают cabinet и служебные сообщения; отметка чтения общая с основной CRM.

## Возможности

- Клиенты: поиск, фильтры менеджера/источника/активности ботов, страницы по 30 записей.
- Карточка: основные контакты и комментарии, создание и редактирование, подписки на каналы,
  события, балансы и последние операции при наличии финансовых прав.
- Создание клиента добавляет событие регистрации в той же транзакции.
- События: список с фильтрами, создание из карточки или с поиском клиента,
  изменение даты, статуса, ответственного, тарифа, суммы и комментария.
- Поля, отсутствующие в мобильной форме, не перезаписываются.
- Проверяется версия карточки перед сохранением. Новые записи имеют устойчивый идентификатор
  операции для повторов после сетевого сбоя.
- Начисление запросов при сохранении события вызывается через существующий TickerInquiryService.
  Напоминания используют общую с основной CRM реализацию.
- Календарь показывает доступные события, разрешённые должностью рекламные кампании и открывает событие внутри Mini App.
  Месяц и фильтры списков сохраняются в URL. При более чем 500 записях показано предупреждение.
  Итог календаря — сумма выполненных доступных событий, а не прежняя сводка всех подсистем.
- Отчёт по тарифам открывает карточку клиента внутри Mini App; его SQL ограничен компанией.

## Этапы 4–6

- В нижнем меню появились «Задачи» и «Ещё». В «Ещё» находятся уведомления, платежи и отчёты.
- Задачи: мои, созданные мной, просроченные, все задачи компании, поиск/статус, страницы по 30.
  Создание, ответственный, срок, категория, важность, статус, закрытие. Проверка версии перед сохранением.
  Комментарии, последние 200 записей. Вложения JPG/PNG/PDF/TXT/DOCX/XLSX/ZIP до 10 МБ,
  сохраняются в Content/Missions, совместимы с основной CRM; скачивание в Mini App проверяет права.
  Используются штатные почтовые уведомления CRM; сбои логируются. На реальную почту тесты ничего не отправляют.
- В карточке клиента: сворачиваемая переписка RTTM/ASHFXPRO, последние 500 сообщений на каждого бота,
  страницы по 30. Явный выбор бота, сообщение только в выбранный Outbox, автоматическое обновление статуса каждые 15 секунд при открытом блоке.
- Уведомления: последние сообщения, ссылка на клиента, количество непрочитанных и кнопка отметки чтения.
- Платежи: период, ID клиента, тип операции; успешные суммы показаны отдельно от незавершённых платежей.
  Оплаты, возвраты, списания; отдельно полный журнал токенов (чтобы не смешивать рубли с проводками токенов).
  Клиент без имени отображается по TelegramId. Дата оплаты и идентификатор YooKassa доступны в записи.
  Выборка строго ограничена компанией, без резервного поиска по всем компаниям.
- Аналитика: переходы из подписчиков, динамика по дням/неделям/месяцам, источники рекламы (admin),
  статистика ASHFXPRO. Канальные отчёты доступны компании 8. Статистика бота ограничена доступными сотруднику клиентами.
  Динамика повторяет расчёт основной CRM: отписки из подписавшихся, группировка по дате подписки,
  8 линий, 4 из них пунктирные. Линии можно выключать, значения доступны также текстом.
  Отчёт переходов больше не изменяет таблицу отписок при чтении.

## Проверка

- `npm run build`: проверка Vue/TypeScript и production-сборка.
- `npm run lint`: ESLint.
- `tests/workspace-smoke.cjs`: локальный preview, Playwright и полностью подменённые ответы CRM.
  Проверяет мобильную навигацию, создание/редактирование клиента, создание/завершение события, задачи, комментарий с вложением, скачивание файла, переписку, отметку чтения, фильтр платежей, все новые отчёты и скрытие действий.
  Для запуска нужен Playwright (можно указать каталог через PLAYWRIGHT_MODULE), на Windows используется установленный Edge.
  Скрипт не допускает обращений к рабочей CRM. Скриншот сохраняется в tests/workspace-mobile.png.
- `ConsGroupCrm/tests/MiniAppWorkspaceSmoke.cs`: автономные проверки соответствия фильтра
  правилам CRM для всех должностей, границы компаний, дат и ключей повторных запросов.

Сборка и автономные тесты не заменяют проверку записи на тестовой БД.
После обновления проверить отдельного сотрудника каждой используемой должности: видимые клиенты,
регистрацию нового клиента, изменение события, начисление по тарифу 44 и напоминания для компании Satory.
Не проверять начисления на реальных клиентах.

Для этапов 4–6 перед публикацией на рабочем сервере проверить на тестовой БД запись в Missions/MissionComments/Outbox и MiniAppOperations, повтор одного RequestId, доступ сотрудников разных компаний и статусы отправки через работающий бот. Эти интеграции требуют настроенной БД; автономные проверки не вызывают рабочие API, YooKassa, Telegram или SMTP.

## Этап 7: остальные разделы

Вход: **Ещё → Остальные разделы CRM**. Разделы и доступные действия определяются на сервере.

- Тарифы, рекламные кампании и площадки, сотрудники, расходы, источники рекламы, продукты, каналы, настройки текущей компании, шаблоны сообщений, должности, тикеры, зарплата, тесты и их вопросы/ответы.
- Списки с поиском и страницами, фильтры периода для расходов/зарплаты/кампаний, создание и редактирование. Удаление доступно администратору только для разрешённых сущностей; связанные записи защищены от удаления. Сотрудники, компания, должности и шаблоны не удаляются через Mini App.
- В кампаниях доступны загрузка и скачивание документов до 10 МБ. Файлы сохраняются в Content/Docs; скачивание проверяет доступ к кампании.
- Сотрудники: основные данные и статусы. Создание/сброс пароля учётной записи CRM доступно только администратору. Директор не может менять привязку Telegram, должность и права входа. Пароли не возвращаются и не записываются в журнал действий.
- Зарплата: записи по сотруднику и месяцу, защита от дубликата. Настройки компании относятся только к компании вошедшего сотрудника; переключение компании не добавлено.
- Общие справочники (должности, шаблоны, тикеры, тесты) доступны администратору. Остальные записи ограничены компанией сотрудника. Observer не редактирует данные.
- Массовые рассылки компании 8: список ID клиентов, предварительный просмотр получателей, отдельное подтверждение. Для каждого клиента выбирается ASHFXPRO, иначе RTTM. Сообщения помещаются в Outbox; история показывает статусы. Повтор запроса с тем же ключом не создаёт повторную рассылку.
- Тесты сотрудников: активные тесты, пять попыток, история и результат. Правильность ответов вычисляется сервером; правильные варианты не передаются до сдачи.
- Журнал действий: период, поиск, записи сотрудников текущей компании, ссылки на сущности. Значения секретных полей скрыты. Запись SqlUtils.LogAction переведена на SQL-параметры; ошибки фоновой записи логируются.
- Сообщения ботов: последние 200 сообщений с привязкой к клиентам текущей компании.

### Публикация этапа 7

Новых таблиц не требуется. Нужна уже предусмотренная dbo.MiniAppOperations из miniapp-stages-4-6.sql: она также защищает новые операции от повторной отправки.
В сборку CRM включены MiniAppCatalog.cs, MiniAppDocuments.cs, MiniAppExams.cs, MiniAppBulk.cs и MiniAppAdministration.cs. Сначала опубликовать сборку CRM, затем весь dist Mini App.
Операции учётных записей предполагают, что DefaultConnection и ClientDBContext указывают на одну БД CRM, как в текущей конфигурации.

### Дополнительные проверки

- ConsGroupCrm/tests/MiniAppCatalogSmoke.cs: 287 автономных проверок полей форм, прав сотрудников, преобразования значений и оценки тестов. Генерирует tests/catalog-fixtures.json из серверных описаний форм.
- tests/catalog-smoke.cjs: мобильный браузер, 16 форм, документы, учётная запись, удаление, сдача теста, предварительный просмотр/подтверждение рассылки, журнал и сообщения ботов. Все API подменены; реальные сообщения не отправляются.
- Перед рабочей публикацией проверить на тестовой БД сохранение справочников, ограничения внешних ключей, повтор RequestId, создание учётной записи и отправку Outbox тестовому получателю. Автономные тесты не проверяют реальную БД и доставку Telegram.

## Главный экран

При запуске открывается сетка разделов: крупные значки календаря, клиентов, событий, уведомлений, отчётов и платежей; ниже — компактные значки остальных доступных разделов. Справочники загружаются из CatalogSections с учётом прав сотрудника. Нижняя кнопка «Главная» и название CRM возвращают к сетке.
Календарь перенесён с / на /calendar; переходы по месяцам сохраняют новый адрес. Для этой смены интерфейса достаточно обновить Mini App (весь dist, включая 404.html), новая сборка CRM не требуется.
